# ADR-051 — Produit Rapide Pro + طبقة السرعة (مقترح معتمد، تنفيذ مباشر)

**الحالة**: `DECIDED + EXECUTING` — اعتُمد من المالك 2026-11-25 (Pro + Speed). التوثيق أولًا ثم التنفيذ P0→P2.
**السلف**: ADR-047 (المكشوف) · v1.8.3 (تحمّل المجهول: FK→NULL بلا خصم) · MKT-004 (جزر POS) · C5 (سجل الاختصارات).

## 1 · المراجعة الأخيرة (ما قبل التنفيذ)
- **R1 — خطر الدمج**: `addCartLine` يدمج على `(product_id, price, packName)` — كل السريع يحمل `id=0` ⇒ تسميات مختلفة بنفس السعر كانت ستندمج في سطر واحد باسم الأول. **الحل المعتمد**: `pack.packName = التسمية` + `name_fr = '⚡ Produit Rapide'` ⇒ السطر «⚡ Produit Rapide [خبز الشعير]» — نفس التسمية+السعر يندمج (صحيح)، المختلفة تنفصل (صحيح). صفر تغيير في `cart-state`.
- **R2 — المفتاح**: `F11` حرّ في الكود (`shortcuts.ts` بلا F11) وفي Tauri webview (لا ربط ملء-شاشة أصلي) ⇒ `pos.rapide: [F11]` + زر مرئي معًا (لا تعارض، لا حاجة للاختيار).
- **R3 — بوابة الصفرية**: بدل بنية PIN جديدة: حارس الدور (`role === 'cashier'` ⇒ شريحة 0% معطلة «يتطلب مديرًا») — يستخدم RBAC القائم + تدقيق قائم.
- **R4 — D1**: لافتة السماح داخل حاوية `lg:flex-row` (تضيق جانبيًا) ⇒ تُنقل خارجها مع نفس الـcommit (إصلاح بنيوي صغير، لا drive-by: نفس شاشة المهمة).
- **R5 — الاتساق المالي**: `pid=0` غائب دائمًا من `products` ⇒ الممرّان (`sqlite.ts:2252` + `fiscal.rs:919`) يُصفّران FK ويتخطيان الخصم ويسمان `was_negative=1` — مثبت بالقراءة، يُثبت باختبار parity.

## 2 · المقترح الكامل (المنظم)
**Pro**: (①) 3 مداخل — مودال F11/زر، إنشاء مضمّن في F7 (لا نتيجة ⇒ صف «⚡ إنشاء: query»)، بلاطات ⚡ مثبّتة في الشبكة. (②) ذاكرة ذكية — سعر/ضريبة/مورّد لكل تسمية + تنبيه قفزة السعر + variants. (③) ترقية لمنتج دائم ≥ 10 مبيعات (باركود `98xxxx`، مخزون 0، التاريخ يبقى). (④) حوكمة — سقف يومي/بائع، PIN/دور للصفرية، سطر `rapide_count/total` في Z (v16).
**Speed**: بحث متسامح (تطبيع عربي + صوتي لاتيني↔عربي + خطأ حرف + ترتيب باركود>اسم>مبيع) + ⏎ يضيف الأول + كمية مضمنة `3*خبز` + شريط الأكثر مبيعًا + أفاتار حرفي ملوّن + «يُشترى معه» (co-occurrence ليلي) + ± على السطر + مسح متواصل + كتابة عالمية. مؤشرات: KPS ≤ 6، بحث < 150ms، صفر شاشات إضافية.

## 3 · مخطط التنفيذ الاحترافي
**P0 — الأساس** (هذه الدفعة): `core/rapide.ts` (بناء/تحقق، `RAPIDE_PID=0`) + `rapide.test.ts` (تكافؤ مجاميع، رفض، شكل السطر) + `QuickProductModal.tsx` (تسمية/سعر/كمية/قطعة-وزن/TVA + حارس الدور) + زر + `pos.rapide:[F11]` (سجل + خريطة + معالج PosView + `rearmBarcode`) + إصلاح D1 + اختبارا parity (TS: FK NULL بلا خصم؛ Rust نظيره موجود ضمنيًا — يُضاف `rapide_no_decrement` لو نقص) + إثبات حي (بيع rapide ⇒ FACT + ظهور Ventes).
**P1 — الذكاء والسرعة**: ذاكرة `baraka_rapide_v1` + F7 المضمّن + البلاطات + وضع الوزن + Most-sold strip + بحث متسامح + ± السطر.
**P2 — الحوكمة**: الأسقف + سطر Z (v16 + هجرة) + معالج الترقية + «يُشترى معه» + لوحة الشذوذ.
**قانون الانحدار**: كل إصلاح/ميزة ⇒ اختبار يفشل قبل وينجح بعد. البوابات: G1 lint ⇒ G2 suite ⇒ G3 cargo (عند مس Rust) ⇒ إثبات حي ⇒ commit نظيف.
