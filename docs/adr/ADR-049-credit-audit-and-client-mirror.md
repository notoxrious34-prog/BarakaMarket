# ADR-049 — تدقيق البيع الآجل + مرآة الزبائن (v1.8.4)

**الحالة**: `DECIDED + EXECUTED` (اعتُمد ضمنيًا بأمر «ابدأ عملية الاصلاح»، نُفذ في v1.8.4).

## 1 · ما سَلِم (لا يُلمس)
- هوية المدين ثلاثية الطبقات: الواجهة تمنع المجهول + الممرّان يرفضان `client inconnu`.
- الترحيل الذري داخل معاملة البيع؛ idempotency عبر `client_sale_id`.
- لا ازدواج طابع: المنح بلا طابع (`ESPECES`-فقط)، التحصيل النقدي يطبع فوق الأصل.
- منع الدفع الزائد (سياق + `max`)؛ عكس الإلغاء/الإرجاع متماثل؛ Z من حقيقة الممر.

## 2 · النتائج والإصلاح
- **F1 (متوسط)**: السقف `max_credit_limit` بلا أي منادٍ — ديكور. الإصلاح: فحص
  **داخل `recordSale`** (ممرّان، بعد الإدخال الإدْمبوتنتي وقبل المعاملة) يرفض
  `CREDIT_LIMIT_EXCEEDED`؛ فحص استشاري في الكاشير لا يحجب الصندوق (المؤقت +
  السبب الواضح + الاسترداد عند رفع السقف).
- **F2 (متوسط)**: إسقاط العالق (`Ignorer`) أبقى دينًا/مخزونًا وهميين؛ إلغاء
  المؤقت مستحيل (`sale not found`). الإصلاح: `reverseProvisionalEffects`
  (عكس بنفس التقريب + حذف الصف الوهمي) عند الإسقاط، ومسار إلغاء مؤقت يعكس
  محليًا عندما لم يرَ الممر البيع.
- **F3 (ملغى بعد الفحص)**: `generateDailyZReport` **حي** (`DailyZReportView:33`
  معاينة/فحص إغلاق + `fetchDailyZ` للحقيقة) — لا حذف.
- **F4 (حرج — لقطة 19/11)**: **صفر مسارات إنتاجية تكتب في `clients` بالممر**
  (المرآة T4c للمنتجات فقط) → كل كريدي لزبون متصفح = `client inconnu` عالق.
  الإصلاح: `client_upsert` (Rust أمر + TS + مسار loopback) **لا يمس الرصيد
  أبدًا** (يُزامن السقف)، جسر `client-authority.ts` (exe + متصفح)، دفع عند
  الإضافة/التعديل + مزامنة جلسة + ضمان قبل تثبيت الكريدي.

## 3 · متبقّى مُوثّق (خارج النطاق)
- إلغاء بيع **مثبت** لا يعيد مخزون المتصفح (حقيقة الممر سليمة؛ تُشفى بإعادة
  التشغيل عبر T4c). يُعالج في حزمة المخزون القادمة إن اعتُمد.
