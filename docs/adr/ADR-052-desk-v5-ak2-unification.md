# ADR-052 — Activation Desk v5: توحيد الإصدار حول AK2

**الحالة**: `DECIDED + EXECUTED` — نُفذ في v1.10.0 (P0).
**السلف**: ADR-002-MKT (التشفير) · ADR-050 (BarakaLock v2) · مكتب التفعيل v4.

## 1 · السياق (ما أثبته تدقيق v4)

المحطة v4 أتقنت *كيف* تُصدر (قفل تسلسلي، 409، رمز مشغّل، نسخة، تدقيق) لكنها
تخلفت جيلاً عن *ماذا* تُصدر: النواة والعميل والمصدِر الخام في عصر AK2
وهي تتكلم v1 فقط. الفجوات المثبتة (F1–F4 في تقرير التدقيق):

- **F1**: لا إصدار ولا تحقق لـ AK2 — مفتاح v2 شرعي يظهر INVALID في المحطة.
- **F2**: لا جهة إصدار لرموز الفكّ `UL-` رغم اعتمادها (ADR-050 §2.5).
- **F3**: الاستبدال خطوتان غير ذريتين رغم وجود `ledgerTransfer` في النواة.
- **F4**: `keygen.ts` يصدر خارج الدفتر (ثقب تدقيقي).

## 2 · القرار

1. **إصدار AK2 من المحطة** (`format: 'v2'` + `v2: {tier, expires, maxVer, hwid2}`):
   التوقيع بنفس مفتاح المالك، تحقق ذاتي عبر `validateEnvelopeKey` قبل العرض.
   الافتراضي في الواجهة v2؛ الـ API يبقى v1 افتراضياً (توافق).
2. **تحقق مزدوج**: v1 أولاً ثم AK2 — الرد يعلن `{format, tier, slot, expired, maxVer}`.
   مفتاح منتهي الدعم = `valid:false + expired:true` (النواة الدائمة لا تتأثر).
3. **رموز الفكّ** (`POST /unlock/issue`): `{hwid, scope, days 1–30, counter}` —
   تحقق ذاتي، **تدقيق فقط** (منح لا تراخيص، خارج دفتر الإيراد).
4. **نقل ذري** (`POST /transfer`): `ledgerTransfer` تحت القفل — إلغاء #قديم +
   إصدار الجديد صفين متجاورين؛ الواجهة تستدعيه بدل issue-then-revoke.
5. **المحرمات**: المفتاح الخاص loopback فقط · معادلة الهاش مجمدة · v1 تبقى صالحة ·
   لا إلغاء عن بُعد (معلن) · لا مساس بمفاتيح العملاء القائمة.

## 3 · ما لم يُفعل (مؤجل صراحةً — P1/P2)

- توحيد/تجميد `scripts/activation-desk.ts` (CLI ما زال v1 بلا تصليب).
- إلزام الدفتر على `keygen.ts`؛ الإيراد الصافي؛ تدوير `desk-audit.log`.

## 4 · البوابات (نُفذت كلها)

`tsc` + اختبارات المحطة (v2 إصدار/تحقق/انتهاء/عبث، UL إصدار/REPLAY، نقل ذري
+ 404/409/400، تدقيق unlock/transfer) + `test` الشامل + `vite build` +
إثبات حي (e2e معزول: v2 → تحقق slot1/slot2 → UL → transfer → سلسلة سليمة).
