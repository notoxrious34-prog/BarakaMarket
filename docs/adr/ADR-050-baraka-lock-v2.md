# ADR-050 — BarakaLock v2: أقوى تفعيل (توثيق معتمد، تنفيذ مباشر)

**الحالة**: `DECIDED + EXECUTING` — اعتُمد من المالك 2026-11-24، التوثيق أولًا ثم التنفيذ P0→P4 مباشرة.
**السلف**: ADR-002-MKT (التشفير) · L1 (إعادة التحقق) · v1.4.5 (قفل الانحراف).

## 1 · ما أثبته التدقيق (قراءة-فقط)

التشفير سليم (Ed25519، لا سرّ في الحزمة، دفتر hash-chain). العيوب في الحواف:
- **W1**: التجربة تُصفَّر بمسح بيانات المتصفح (localStorage فقط).
- **W2**: قفل كاذب للزبون الدافع (seed ضائع / UA متغيّر → HWID جديد → قفل).
- **W3**: إرجاع الساعة يمدّد التجربة (لا سقاطة رتيبة).
- **W4**: لا إلغاء فعلي (العميل لا يفحص دفتر الإلغاء).
- **W5**: المفتاح بلا دورة حياة (لا طبقة/انتهاء/سقف نسخة/نقل).
- **W6**: الإنفاذ في الواجهة فقط (الممر المالي لا يعرف الترخيص).
- **W7**: نافذة ثقة عند الإقلاع (علم ACTIVATED تزامني قبل إعادة التحقق).
- **W8**: Ed25519 WebCrypto قد يغيب في WebView قديم (رفض سليم لكن بلا بديل).

## 2 · القرار: مظروف AK2 + بصمة أصلية + إنفاذ الممر

### 2.1 المظروف `AK2-<b64(json)>.<b64(sig)>` (موقّع كاملًا بنفس المفتاح)
| حقل | المعنى |
|---|---|
| `ver: 1` | إصدار المظروف (+ `pubkey_id` لتدوير مستقبلي) |
| `tier: PERP\|SUPPORT12` | دائم / دعم سنوي (النواة الدائمة لا تنتهي أبدًا) |
| `issuedMs / expiresMs?` | الإصدار / انتهاء عقود الدعم فقط |
| `maxVer?` | سقف النسخة (ترقية رئيسية مدفوعة) |
| `hwid1 / hwid2?` | الأساسية + **الاحتياطية** (قاتلة W2: استبدال شرعي ذاتي) |
| `features` | قناع مزايا مستقبلي |
الحمولة الموقّعة: `BM-V2|ver|tier|issued|expires|maxVer|hwid1|hwid2|features|STORE|`.
مفاتيح v1 (`AK-…`) تبقى صالحة (توافق رجعي — لا كسر لمحل مفعّل).

### 2.2 البصمة الأصلية (ممر الـexe، بلا حزم جديدة)
أمر `machine_hwid` (Rust، std فقط): `MachineGuid` عبر `reg query` (مخبّأ في meta)
+ احتياطي `COMPUTERNAME` + `ARCH`. الصيغة `arch|hostname|os|seed` **ثابتة**
(تغييرها يكسر مفاتيح v1) — الاستقرار يأتي من المصادر لا الصيغة.
**لماذا يكفي ضد الاستنساخ**: نسخ ملف القاعدة لجهاز آخر ينقل الـseed لكن
`MachineGuid` يختلف → انحراف → قفل. (DPAPI أُسقط عمدًا: يتطلب crate جديدًا،
والربط بالبصمة يحقق نفس الأثر.)
ممر المتصفح يبقى «أفضل جهد» (حدّ صادق: لا وصول للعتاد).
**الهجرة بلا كسر**: `legacyHwid` (الصيغة القديمة) مقبول بتحذير فقط — لا قفل.

### 2.3 مرساة التجربة + السقاطة (قاتلا W1/W3)
- `meta.trial_epoch` تُكتب مرة واحدة (`INSERT-or-ignore`) + عدّاد المبيعات من
  جدول `sales` المالي. مسح المتصفح = لا شيء. (محل قديم بلا مرساة: تُختم عند
  أول بيع — تمديد لمرة واحدة موثّق ومدقّق.)
- `meta.license_last_seen_ms` (max-clock في التخزينين): `now < lastSeen − 1h`
  = عبث ← قفل برسالة + رمز فكّ (W3 مغلقة).

### 2.4 إنفاذ الممر (قاتل W6)
`recordSale` (الممرّان) يقرأ `meta.license_state` + `trial_epoch` + العدّاد:
مفعّل صالح (توقيع/ربط/طبقة/انتهاء) أو تجربة حيّة أو سماح/تجاوز ساريان —
وإلا `LICENSE_EXPIRED`. **غياب البيانات = سماح** (لا كسر لمحل قديم).
صدق موثّق: الممر الأصلي يفرض الربط والميزانيات؛ أصالة التوقيع تُفرض عند
الإقلاع (TS) + الواجهة — تزوير ملف القاعدة محليًا يتطلب مهارات SQLite ولا
يمنح إلا تمديد تجربة (خطر متبقٍّ مقبول ومعلن).

### 2.5 رموز الفكّ + السماح + التجاوز (P3/P4)
- رمز `UL-<b64>.<b64sig>` موقّع بنفس المفتاح: `(hwid||counter||expiry||scope)` —
  استعمال واحد عبر `meta.unlock_counter` (عبث/انحراف/طوارئ).
- سماح 3 أيام بلافتة بعد الانتهاء (الجمعة/الأعياد) ثم قفل صلب.
- تجاوز مالك 24h برمز PIN + تدقيق (`meta.override_until`).
- الإلغاء عن بُعد مستحيل offline — يُقال صراحةً؛ البديل: مفاتيح قصيرة +
  رفض إعادة التفعيل + صف `transfer` في الدفتر (الصيغة مجمّدة، النوع يتدفق).

## 3 · خطة التنفيذ P0→P4 (نفس الجلسة)
P0 مظروف+مفاتيح+دفتر · P1 بصمة أصلية+مرساة+هجرة · P2 إنفاذ الممرّين ·
P3 رموز الفكّ · P4 سماح/تجاوز/واجهة. كل مرحلة: RED-GREEN + G1–G5 + إثبات حيّ.
الإصدار: **v1.9.0** (ميزة جديدة).
