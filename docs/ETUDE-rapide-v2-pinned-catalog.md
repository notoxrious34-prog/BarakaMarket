# دراسة تطوير Produit Rapide v2 — «كتالوج خفيف مثبّت» (Pinned Lite Catalog)
**الحالة:** دراسة قرار (DECISION STUDY) — بدون تنفيذ · **التاريخ:** 2026-11-25 · **المرجع:** امتداد ADR-051 (P0/P1/P2 مشحونة في v1.9.1/v1.9.2)

---

## 0. الملخص التنفيذي لصاحب القرار

**المشكلة بجملة:** أصناف دائمة بلا باركود (بيض، حلوى، جبن، بقوليات…) تعيش في المخزون **بهويات وهمية**، لأن النظام لا يملك لها بيتًا شرعيًا.

**الحل المقترح بجملة:** صنف حقيقي بـ`barcode = NULL` + نوع (`PIECE / POIDS / LIBRE`) + تثبيت مركزي (بلاطات + F-keys) + وضع ميزان (وزن ⇄ سعر/كغ) — مع إبقاء `prix libre` العابر كملاذ طوارئ.

**لماذا الآن؟** P0/P1/P2 بنت الأساس (سطر حر + ذاكرة + سقوف + مذكرة Z). الكلفة الحدّية لـP3 منخفضة، والعائد يقتل جذر الأكواد الوهمية.

**المطلوب منك:** اعتماد النطاق (P3 وحده أم P3→P5) + الإجابة على الأسئلة المعلّقة في §10. لا يُبنى شيء قبل الاعتماد.

## 1. التشخيص الكمّي (لماذا يستحق الاستثمار؟)

| المؤشر | الوضع الحالي (أكواد وهمية) | المستهدف بعد v2 |
|---|---|---|
| زمن بيع صنف بلا باركود (ذروة) | ~15-30 ثانية (تذكّر كود/بحث) | **< 5 ثوانٍ** (بلاطة/مفتاح) |
| أصناف بهوية مزوّرة في المخزون | كل أصناف الميزان والحلوى | **صفر** (حارس منع + ترحيل) |

| خطأ التصادم (كود وهمي = حقيقي لاحقًا) | ممكن بصمت | **مستحيل إنشائيًا** |
| تدريب كاشير جديد على الأصناف | حفظ أكواد + شرح شفهي | **بصري**: بلاطات ملوّنة + أسماء |

> قاعدة القياس: تُقاس كل مرحلة بنفس البروتوكول (مسبار playwright +lovelace lane) قبل/بعد — لا ادعاءات بلا أرقام.

## 3. التصميم المقترح (Solution Design)

### 3.1 نموذج البيانات (امتداد غير كاسر)

```
produit: barcode NULLABLE UNIQUE (NULL = شرعي بلا باركود، يتكرر بحرية)
         + kind: PIECE | POIDS | LIBRE        (جديد)
         + price_per_kg_ct / tva_rate / unit  (موجودة، تُملأ إلزاميًا لـPOIDS)
         + pin_order INT NULL + pin_color/icon (جديد — NULL = غير مثبّت)
         + track_stock BOOL default false      (جديد — §5)
         + pinned_until DATE NULL              (جديد — O3 موسمي)
```

- **لا هجرة كاسرة**: أعمدة جديدة NULL-able + `LATEST_SCHEMA_VERSION + 1` بنفس بروتوكول v16 (هجرة idempotent في الممرّين).
- `*PRIX-LIBRE*` + `pid 0` يبقيان **كما هما** للحالات العابرة (J2/J11) — لا يُمسّ ADR-051.

### 3.2 وضع الميزان (Pesée) — القواعد الحسابية

- الإدخال إما **وزن (غ)** أو **سعر إجمالي (ct)** — الاتجاه الآخر يُشتق ويُعرض.
- `line_ttc = round_half_up((weight_g − tare_g) × price_per_kg / 1000)` — سنتيم دائمًا (الدستور).
- Tare اختيارية/صنف (وزن العلبة المعتاد يُحفظ مع الصنف).
- الوحدة تُطبع (`g`/`kg`) امتدادًا لـ`display.formatGrams`.

### 3.3 السرعة (ميزانيات أداء ملزمة)

- نقرة البلاطة → سطر في السلة: **< 100ms** إحساسًا (optimistic UI + `memo` — حراس `pos-split` قائمة).
- فتح POS/الشبكة: لا انحدار عن baseline (`median 225ms←30ms` محفوظة).
- البحث: المثبّتات أولًا + التسامح الموجود (`search-smart`) + مرادفات دارجة تُضاف لملف واحد (`بيض/عضم/œufs`…).

### 3.4 الضوابط (تُبنى مع الميزة لا بعدها)

- حارس **anti-fake** عند إنشاء منتج: كود يطابق أنماطًا وهمية (قصير/متسلسل/مكرر) ← تحذير + اقتراح `NULL barcode`.
- سقفا P2 يُعمَّمان (عام + خاص مثبّتات، `meta KV`).
- صلاحيات: إنشاء/تثبيت/تعديل = **مالك فقط** (`AuditAction` جديدة: `catalog.pin/unpin/price`)؛ الكاشير يبيع فقط.
- prix libre يبقى للكاشير (طوارئ) تحت السقف.

## 4. التوافق الدستوري (Constitution Mapping — غير قابل للتفاوض)

| مبدأ | التطبيق في v2 |
|---|---|
| سنتيم + HALF_UP + milli-unités | كل حسابات الوزن بالسنتيم؛ الوزن milli-gram داخلیًا |
| TVA 0/9/19 + Timbre + Art.136 | TVA لكل صنف (لا افتراض)؛ السطور تدخل نفس `FiscalTotals`؛ الآجل بنفس السقف |
| `seq` مملوك SQLite + Z hash-chain | **لا يُمسّان** — التفصيل الجديد مذكرة إعلامية خارج السلسلة (قاعدة P2) |
| Dual-lane parity | كل قاعدة تُنفَّذ في `sqlite.ts` + `fiscal.rs` معًا + اختبار parity |
| Regression law | كل إصلاح/ميزة يشحن باختبار **يفشل قبل ويمرّ بعد** |
| Zero-scrollbar / `.dark` / `tabular-nums` | البلاطات الجديدة تخضع لـ`final-sweep` (AR/FR × dark/light) |
| Keyboard-first | ربط F-keys في `docs/KEYBOARD-MAP.md` + لا فخاخ تركيز |

## 6. البدائل المدروسة والمرفوضة (بأسباب — لا تخمين لاحق)

| البديل | لماذا رُفض؟ |
|---|---|
| طباعة باركود داخلي لكل صنف ميزان | كلفة طابعة + ملصقات + صيانة؛ لا يحل الجبن المقطوع بأوزان متفاوتة |
| ربط إجباري بميزان إلكتروني | الميزان قد يتعطّل (J11)؛ الحل يجب أن يعمل **بدون عتاد** |
| prix libre فقط (توسيع P0) | يُبقي البيع مجهول الهوية (O1/O5) ولا يحمل سعر/كغ ولا TVA صحيحة |
| أصناف عادية بكود وهمي «منظّم» (نطاق محجوز) | شرعنة الوهم بدل قتله؛ التصادم يبقى ممكنًا؛ الجرد يبقى ملوثًا |
| تتبّع مخزني كامل للمثبّتات | مبالغة تشغيلية (وزن كل كيس عدس مستحيل) — التتبّع **اختياري** (§3.1) |

## 7. خطة الطرح (P3 → P5) ومعايير القبول

### P3 — الأصناف المثبّتة (الأولوية القصوى)
- [ ] هوية NULL + `kind` + تثبيت مركزي + بلاطات + F-keys + `N*بلاطة`
- [ ] حارس anti-fake + صلاحيات مالك + تدقيق
- [ ] إرجاع السطور المثبّتة (اختبار صريح)
- [ ] **DoD**: بيع J1 < 3 ث مُقاسًا · 0 كود وهمي جديد ممكن · parity + `final-sweep` أخضر

### P4 — وضع الميزان
- [ ] وزن ⇄ سعر + tare + طباعة الوحدة + تفصيل Z (مذكرة)
- [ ] B3 non-régression مختبَرة · **DoD**: J3 < 8 ث · حسابات سنتيم مُبرهنة

### P5 — الترحيل والذكاء
- [ ] تقرير الأكواد المشبوهة + اعتماد صنف-صنف + backup/تراجع
- [ ] اقتراح «ثبّت هذا؟» عند تكرار نفس prix libre ≥ N مرات
- [ ] **DoD**: 0 صنف وهمي نشط · التاريخ القديم سليم · تقرير مالك

**المؤجَّل صراحةً:** صور الأصناف · ملصقات داخلية · multi-magasins.

## 8. استراتيجية الاختبار (لكل مرحلة)

1. اختبار parity ممرّين لكل قاعدة (TS + Rust).
2. اختبار قبول زمني (playwright: J1/J3/J6 بالكرونو).
3. اختبار انحدار: B3 + prix libre + caps P2 + إغلاقات Z.
4. `final-sweep` بصري للبلاطات الجديدة (AR/FR × dark/light × 1024×650).

## 9. الأثر على الموجود (تقييم صريح — لا مفاجآت)

- `QuickProductModal`/`PosRapideTiles`/`usePinnedRapides`: **تتوسّع** (التثبيت ينتقل مركزيًا، المحلي يبقى fallback) — لا حذف.
- السكيما: `+1` فقط، أعمدة NULL-able — الجدّ والزبائن القدامى بأمان.
- المطبوعات: تتوسّع (اسم + وزن) دون تغيير التخطيط الضريبي.
- الأداء: البلاطات `memo` + تجنّب re-render (حراس قائمة).

## 10. الأسئلة المعلّقة على المالك (بدون إجابتها لا يُبنى P3)

1. **الكمية/السعر الافتراضي للبلاطة**: آخر استعمال أم قيمة يحددها المالك لكل صنف؟
2. **مفاتيح F**: أي F-keys تُحجز للمثبّتات؟ (توجد F1/F7/F9/F11 مشغولة — أقترح F2/F3/F4 إن شاغرة)
3. **التتبّع المخزني**: أي أصناف تتتبّع فعليًا (بيض بالطبق؟) أم الكل بلا تتبّع مبدئيًا؟
4. **سعر/كغ الافتراضي**: من آخر prix libre أم إدخال يدوي عند التثبيت؟
5. **نطاق P3**: المثبّتات فقط، أم مع حارس anti-fake وأداة الترحيل في نفس الشحنة؟
