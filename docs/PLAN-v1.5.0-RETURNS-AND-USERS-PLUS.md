## الجزء 1: الإرجاع — التصميم العميق (B1)

### 1.1 المبدأ الذهبي
الإرجاع **ليس حذفاً ولا تعديلاً** — هو **صف مالي جديد معاكس** مرتبط بالأصل (append-only، نفس فلسفة `void_sale` و`zclose`). البيع الأصلي يبقى شاهداً للأبد.

### 1.2 النطاق المدروس (مصفوفة الاحتمالات)
| الحالة | القرار المقترح | السبب |
|---|---|---|
| إرجاع كلي / جزئي لسطر | مسموح، بحد تراكمي ≤ الكمية المباعة | يمنع "إرجاع 3 من بيع 2" |
| إرجاع بعد إغلاق Z اليومي | مسموح، يُقيَّد في **اليوم المفتوح الحالي** كـ AVOIR مرتبط بالـ FACT الأصل | الأيام المقفلة مجمدة قانوناً (t11) — لا تُمس |
| إرجاع بعد N يوم | عتبة قابلة للضبط (مقترح: 7 أيام، ⏳ قرار المالك) | يمنع إرجاعات الأشباح |
| منتج موزون (ميزان) | مسموح فقط بوزن جديد فعلي | لا وزن تقديري |
| سريع التلف | تحذير صريح + يتطلب موافقة مدير | حماية المخزون |
| استرداد نقدي / بطاقة | نقدي: حركة صندوق خارجة؛ بطاقة: مذكرة تشغيلية "استرداد عبر الطرفية" + تدقيق | لا نعيد شحن البطاقة من النظام |
| إرجاع بلا فاتورة أصلية | **مرفوض** — يُوجَّه لمسار الخسائر (loss) الموجود | بلا أصل = هبة، not إرجاع |

### 1.3 البنية (نفس لغة المشروع)
- جدول `returns`: ‏(id, sale_ref FACT, product, qty_milli, refund_ct, reason, actor, approver, day, seq)‏ + تسلسل `RET-YYYY-######` بنفس محرك الـ sequencer (بلا فجوات).
- مساران ثلاثة: `return_create` (cashier يُنشئ مسودة) → `return_approve` (manager/owner، قاعدة الشخصين فوق العتبة ⏳) → `return_reject`.
- المخزون يعود بالملي (نفس حساب `colisage`)؛ الصندوق يخرج بحركة موثقة؛ Z اليوم المفتوح يجمع **الصافي** (مبيعات − إرجاعات).
- إيصال حراري "وصل إرجاع BON DE RETOUR": الـ FACT الأصلي + المبلغ + سببه + سطرا توقيع.
- تدقيق: `return.created/approved/rejected` — كل صف باسم الفاعل والمُعتمِد.
- البوابات: اختبارات T-lane (الحراس، حساب الملي، السقف التراكمي، أثر Z، الصلاحيات) + حديدية قصيرة قبل النشر.

### 1.4 المخاطر المتبقية (بصراحة)
- المعالجة الجبائية للإرجاع عبر الأيام (avoir رسمي) تحتاج **رأي المحاسب** — التصميم أعلاه سليم محاسبياً كمبدأ (صف معاكس مرتبط) لكن الصيغة القانونية للوثيقة ⏳ تُستكمل مع المحاسب قبل الطباعة النهائية.

## الجزء 2: Utilisateurs Plus — مقترحات عالمية (B2، بعد الإرجاع)
1. **سبب التجميد إجباري** (قائمة: استقالة/إجازة/سوء استخدام/أخرى + ملاحظة) — رخيص، قيمة تدقيقية عالية. ← أولوية قصوى.
2. **الخط الزمني للمستخدم**: كل أفعاله من الـ audit في صفحة واحدة (بحث/تصفية/تصدير CSV بالبنية الموجودة).
3. **كلمة مؤقتة بعمر**: PIN صالح N ساعة للبدلاء، ينتهي تلقائياً.
4. **تدوير إجباري دوري**: كل N يوم (قابل للضبط، افتراضي 90) مع تذكير قبل 7 أيام.
5. **قاعدة الشخصين**: إنشاء مالكٍ ثانٍ يتطلب تأكيد مالك موجود + توثيق مضاعف (اليوم: confirm واحد).
6. **جلسات حية وإسقاط**: قائمة الداخلين الآن + زر إسقاط الجلسة (للمالك).
- خارج النطاق صراحةً: البصمة/SSO (محل واحد، تكلفة بلا عائد).
