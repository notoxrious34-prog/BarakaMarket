# RUNBOOK — الجلسة الحديدية v1.4.10 (بعد إغلاق المحل)

**القاعدة:** لا عبث بقاعدة الإنتاج. كل خطوة أدناه على **ملف اختبار معزول**، وحالة الصفر-أثر بعده.

## التحضير (5 دقائق)

1. نسخة ساخنة: `BackupManagerView → إنشاء نسخة فورية` + نسخة USB خارجية.
2. سجّل القيم المرجعية من القاعدة الحية (قراءة فقط): عدد المبيعات، آخر `FACT-`، رصيد الطابور `0`.
3. أنشئ مجلد اختبار معزول (انظر §9 من تقرير الجلسة: `APPDATA` مُتجاوَز + حذف `EBWebView` **بعد نسخه احتياطياً**).

## التنفيذ (15 دقيقة)

| # | الخطوة | المتوقع | الدليل المطلوب |
|---|---|---|---|
| 1 | تنصيب v1.4.10 نظيف على المجلد المعزول | إقلاع + عذرية `0/0/0/0` | لقطة الشاشة + عدّ الصفوف |
| 2 | دخول المالك الحقيقي | دخول ناجح + شارة الجلسة | اسم المستخدم + الوقت |
| 3 | إنشاء مستخدم `t10-cashier` (cashier/PIN مؤقت) من صفحة Utilisateurs | نجاح + `must_change_pin=1` | صف `user.create` في Audit |
| 4 | دخول `t10-cashier` → شاشة التغيير الإجباري → تغيير PIN | إجبار + خروج تلقائي + دخول جديد ناجح | لا تجاوز ممكن |
| 5 | تجميد `t10-cashier` ثم تفعيله | رفض الدخول أثناء التجميد + نجاح بعده | صفّا `user.deactivate` في Audit |
| 6 | تأكيد إغلاق Z اليومي (لقطة الحوار الناقصة §12.1) | حوار التأكيد يظهر بالنص الكامل | لقطة شاشة |
| 7 | بيع نقدي حي واحد | `FACT-` متسلسل + طابور `0` + مخزون منقوص | أرقام الفاتورة |

## التنظيف (5 دقائق)

1. حذف مجلد الاختبار المعزول بالكامل.
2. استعادة `EBWebView` الأصلي من النسخة الاحتياطية.
3. التحقق: القاعدة الحية كما كانت (الأعداد المرجعية مطابقة).
4. إلحاق الأرقام واللقطات بتقرير الجلسة — عندها فقط يُفتح باب A5 (النشر).
