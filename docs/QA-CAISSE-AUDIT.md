> معيار Microsoft: كل كلمة في الكود مقروءة، كل عملية مُتتبعة من الزر حتى القرص.
> النطاق: `CashSessionsView.tsx` (189 سطر) + `server /api/cash/*` + `sqlite` النقدي + سلسلة Z + التدقيق + الطباعة.

## 1) الخريطة المعمارية

```
[CashSessionsView] ──POST open/movement/close──▶ [loopback :3100 + token] ──▶ [sqlite]
        │ GET /api/cash/active (مفتوح، قراءة حية)         │ BEGIN IMMEDIATE txn
        │                                                     openCashSession / recordCashMovement
        ▼                                                     getCashSessionStatus (نظري حي)
[msg + offline banner]                                    closeCashSessionAndGenerateZ (Z + hash + قفل يوم)
                                                              │──▶ audit z.close ──▶ thermal spool
```

- **القراءة مفتوحة** (GET بلا توكن): الجلسة الحية والنظري يعملان في كل مسار.
- **الكتابة محروسة** (POST + `x-baraka-loopback`): التوكن مولود بجانب الـDB ويُرحَّل عبر `invoke('loopback_token')`.
- **النظري** = افتتاح + نقدي + تحصيل ديون نقداً + إيداعات − سحوبات − مصاريف. التحصيل يحسب `total_collected` (الأصل + الطابع — كلاهما في الدرج فعلاً ✓).
- **نافذة التجميع** `[opened_at, now/closed_at]` من ساعة الخادم نفسه — لا انحراف زمني.
- **الإغلاق ذري**: `BEGIN IMMEDIATE` + رقم Z + سلسلة hash + تحديث الجلسة، و`ROLLBACK` عند أي خطأ.
- **المبيعات المؤقتة مستبعدة** (`status='COMPLETED'` فقط) ✓. الكريدي لا يدخل النظري نقداً، وتحصيله لاحقاً يدخل عبر التسويات ✓.
